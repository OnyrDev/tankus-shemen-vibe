# Архитектурные заметки (DESIGN NOTES) — TANKUS

Этот документ фиксирует ключевые технические и архитектурные решения проекта для предотвращения технического долга.

---

## 1. Сетевая архитектура и транспорт

- **Фасад над MultiplayerPeer:** Геймплейный код (`Tank`, `Weapon`, `Projectile`, `MatchController`) не имеет прямых зависимостей от `ENetMultiplayerPeer`. Все операции с сессией, пирами и лобби инкапсулированы в синглтоне `Network` (`res://autoload/network.gd`).
- **Server-Authoritative:** Хост является единственным источником истины для:
  - Координат и физических столкновений
  - Запаса здоровья и нанесения урона
  - Спавна снарядов и расчёта рикошетов
  - Генерации и валидации драфта карт
- **Клиентский ввод:** Удаленные клиенты отправляют хосту исключительно свои намерения (вектор перемещения, 3D точка прицела, нажатия кнопок стрельбы, прыжка и блока). Локально клиент интерполирует перемещение и мгновенно визуально ориентирует локальную башню для отзывчивости.

---

## 2. Разделение ответственности танка (Component-based Tank)

Сцена танка разделена на независимые слои:
1. `tank_input.gd` — сбор ввода игрока (в сети активен только для владельца `is_multiplayer_authority()`).
2. `tank_controller.gd` — шасси, физика разгона, поворот корпуса за вектором движения, прыжок, гравитация.
3. `turret.gd` — независимый доворот башни на мировую точку прицеливания со сглаживанием угловой скорости.
4. `weapon_component.gd` — логика магазина (4 снаряда), тайминг огня (0.55 с), перезарядка (1.8 с), отдача ствола.
5. `block_component.gd` — окно неуязвимости (0.35 с), кулдаун (3.0 с), уничтожение заблокированных снарядов.
6. `health_component.gd` — здоровье (100 HP), получение урона, визуальная вспышка, смерть.

## 3. Карточная система способностей (Event-driven)

- **Исключение Giant Switch:** Карты не используют один огромный `match card_id` блок. Каждая способность представлена ресурсом `CardDefinition`, который связывается со скриптом эффекта.
- **Событийная шина танка:** Эффекты подписываются на стандартные события:
  - `on_shot(projectile)`
  - `on_projectile_hit(target, projectile)`
  - `on_projectile_bounce(projectile, normal)`
  - `on_block_started()`
  - `on_successful_block(blocked_projectile)`
  - `on_jump()`, `on_land()`
  - `on_damage_taken(amount, attacker)`
- **Чистый пересчёт статов:** `TankStats` вычисляет актуальные характеристики как `derived_stat = base_stat * multiplier + flat_bonus` каждый раз при изменении билда, исключая накопление ошибок `float`.

## 4. Камера и схема управления (Third-Person / TPS)

- **TPS с пружинным подвесом (`SpringArm3D`):** Вместо фиксированного Top-Down ракурса используется динамический вид от 3-го лица с подвесом на `SpringArm3D` (сферический коллайдер `0.22m`, предотвращающий прохождение сквозь стены).
- **Захват мыши (`MOUSE_MODE_CAPTURED`):** Свободное вращение камеры игроком (Yaw/Pitch с ограничением по вертикали).
- **Прицеливание через центральный луч:** Прицеливание осуществляется рейкастом из центра экрана активной камеры прямо вперед в 3D мир. Башня (`Turret`) плавно доворачивает и сводит ствол в точку прицела.
- **Ориентация движения:** Вектор WASD проецируется на плоскость XZ относительно взгляда камеры (W — вперед по направлению взгляда камеры). Корпус танка плавно доворачивается за направлением перемещения.

## 5. Аудиосистема и управление музыкой (MusicManager & Audio Buses)

- **Архитектура аудиошин (`default_bus_layout.tres`):**
  - Создана иерархия шин: `Master` -> `Music` и `SFX`.
  - Все плееры фоновой музыки направляются строго в шину `Music`. Это позволяет независимо регулировать громкость музыки в меню настроек, не затрагивая звуковые эффекты стрельбы и окружения.
  - Fail-safe защита: при инициализации `MusicManager` проверяет наличие шины `Music`. Если разметка шин не загружена или повреждена, шина создаётся динамически через `AudioServer`.
- **Глобальный менеджер (`res://autoload/music_manager.gd`):**
  - Зарегистрирован как Autoload-синглтон (`MusicManager`), существующий независимо от загрузки/выгрузки сцен карт и меню.
  - Имеет `process_mode = PROCESS_MODE_ALWAYS` (музыка не прерывается во время паузы игры).
  - Управляет двумя параллельными узлами `AudioStreamPlayer` (`_player_a`, `_player_b`) для обеспечения бесшовного перекрестного затухания (**Crossfade**) через `Tween`.
- **Управление треками и жизненный цикл (FSM):**
  - При запуске проекта автоматически запускается тема меню (`res://assets/audio/music/menu_theme.ogg`) с плавным нарастанием громкости (Fade-in).
  - Интеграция с циклом матча через сигнал `Game.match_state_changed`:
	- При переходе в фазу обратного отсчета (`COUNTDOWN`) или боя (`PLAYING`) тема меню плавно затихает (`stop_music(1.5)`), освобождая звуковое пространство под SFX танкового боя.
	- При завершении раундов и возврате в лобби (`LOBBY` / `IDLE`) тема меню плавно возобновляет звучание (`play_menu_music(1.5)`).
  - В одиночной песочнице: при закрытии меню сетевой игры музыка плавно глушится для комфортного тестирования механик; при нажатии `Esc` меню и музыка возвращаются.
- **Требования к трекам и бесшовный луп (Loop):**
  - Для музыки используется исключительно формат **OGG Vorbis (`.ogg`)** — малый вес, потоковое чтение без нагрузки на RAM и поддержка нативного бесшовного зацикливания.
  - В параметрах импорта файла (`.import`) выставлен флаг `loop = true`.
  - В коде `MusicManager` дополнительно гарантируется флаг `loop = true` для потоков `AudioStreamOggVorbis`.
- **API для разработчиков:**
  - `MusicManager.play_music(stream: AudioStream, fade_duration: float = 1.0)` — включить трек с плавным кроссфейдом со старого на новый.
  - `MusicManager.play_menu_music(fade_duration: float = 1.0)` — запустить стандартную тему меню.
  - `MusicManager.stop_music(fade_duration: float = 1.0)` — плавно заглушить и остановить текущую музыку.
  - `MusicManager.set_music_volume_linear(linear: float)` — регулировка громкости (0.0 .. 1.0) для UI слайдеров настроек (с автоматическим переводом в децибелы и мьютом при `<= 0.0001`).
  - `MusicManager.get_music_volume_linear() -> float` — получение текущей линейной громкости.
